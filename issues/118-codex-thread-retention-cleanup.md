## Problem

Veduta's ChatGPT subscription Model connection creates a fresh Codex thread for each provider call
and does not resume provider threads. Veduta already owns and persists the canonical conversation
and tool history through its AgentRunner boundary.

The current `thread/start` request omits `ephemeral`. In the exactly pinned Codex 0.146.1 protocol
the field is optional, and the runtime resolves an omitted value to `false`. Codex can therefore
persist a second copy of prompt, context, and tool-turn data inside the connection's `CODEX_HOME`.
The data root backup stages that directory as part of the normal encrypted backup.

Removing a ChatGPT subscription connection invokes `account/logout` and removes its registry
record, but it does not evict the connection's pooled app-server transport or delete its
`CODEX_HOME`. The registry intentionally continues when provider logout fails, which can leave
local credentials and retained thread data behind with no remaining Model connection record.

## Verified behavior

- The production Codex turn starts each thread without `ephemeral`.
- ADR-0014 states that Veduta starts one thread per turn with no provider thread reuse or resume.
- Codex 0.146.1 declares `ThreadStartParams.ephemeral` as optional and applies
  `ephemeral.unwrap_or_default()`; its effective configuration documents that `false` persists the
  session.
- The Codex session pool supports per-connection lookup and daemon-wide shutdown, but no
  per-connection close or eviction.
- Model connection removal tolerates a failed adapter revoke and persists the local removal without
  cleaning the provider-owned directory.
- Backup staging copies non-SQLite data-root trees, including the per-connection Codex directory.

Upstream evidence is pinned to the exact supported source commit:
[thread/start protocol](https://github.com/openai/codex/blob/9d00bb01c0a712fb7c2f5b002bdf33bcc0fc352c/codex-rs/app-server-protocol/src/protocol/v2/thread.rs#L57-L109)
and
[effective ephemeral default](https://github.com/openai/codex/blob/9d00bb01c0a712fb7c2f5b002bdf33bcc0fc352c/codex-rs/core/src/config/mod.rs#L913-L917).

## Goal

A ChatGPT subscription connection retains only the Codex state required for authorization and
operation. Veduta-created inference threads are ephemeral, legacy provider thread history is
removed safely without forcing reauthorization, and removing a connection leaves neither a live
child process nor its local Codex state behind.

## Acceptance criteria

- [ ] Every Veduta-created Codex `thread/start` request explicitly sets `ephemeral: true`, including
      tool-capable turns, and a protocol-level test asserts the exact outbound parameter.
- [ ] Successful, failed, aborted, and timed-out provider calls do not leave resumable thread,
      rollout, or conversation-history artifacts in that connection's `CODEX_HOME`.
- [ ] On upgrade, recognized legacy Codex thread and rollout artifacts are removed idempotently
      before they can be backed up, while credentials and runtime state required by an active
      connection are preserved.
- [ ] An already-authorized connection remains authorized and can catalog, verify, and run inference
      after legacy cleanup without a new device-code login.
- [ ] Removing a Codex connection closes and evicts its pooled transport before deleting that
      connection's entire `CODEX_HOME`; success does not depend on `account/logout` succeeding.
- [ ] Removal during an in-flight request or transport creation cannot recreate the deleted
      directory or leave an app-server child alive. The interrupted call fails through the existing
      unavailable/revoked behavior without executing a duplicate effect.
- [ ] Cleanup is restricted to a schema-valid connection id below the data root's Codex directory.
      It never changes another connection's state or directory, and unknown provider-owned entries
      are not recursively guessed at.
- [ ] A backup created after startup cleanup contains no legacy or newly produced Codex thread
      history. The encrypted backup format and the existing treatment of active Codex credentials
      remain unchanged.
- [ ] Deterministic tests cover exact thread parameters, idempotent legacy cleanup, successful and
      failed logout, multiple connections, active/pending pooled transports, path confinement, and
      backup staging.
- [ ] ADR-0014, the security documentation, and the real-account Codex smoke procedure describe
      ephemeral threads, legacy cleanup, and local state deletion accurately.
- [ ] `pnpm check` passes.

## Scope boundary

- Veduta's own SessionStore, conversation retention, Event log, and diagnostic Trace policies do
  not change.
- This does not add provider-thread resume or reuse.
- Codex command execution, filesystem patches, web search, MCP, native approvals, and other
  provider-native tools remain disabled.
- The exact Codex version pin, backup encryption and format, and the decision to keep active Codex
  credentials outside the vault remain unchanged.
- Top-level discoverability of the ChatGPT subscription path is tracked separately.
