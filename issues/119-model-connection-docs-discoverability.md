# 119 — Expose ChatGPT subscription support in top-level documentation

> _This was generated by AI during triage._

## Problem

Veduta's top-level documentation still presents model access as BYOK-only. The README's
foundational decisions say “VPS-first, passkeys, BYOK”, while the system-at-a-glance diagram names
only “LLM providers (BYOK)” with Anthropic, OpenAI, and OpenRouter.

The shipped product instead uses the broader Model connection contract. It supports API-key BYOK
and a ChatGPT subscription through an exactly pinned `codex app-server`, with a documented
successful real-account smoke. Claude subscription remains visibly unavailable because Anthropic
has not approved a third-party subscription path. The inference-only boundary and Codex
dynamic-tool translation are documented in ADRs and deep references, but a reader must already
know where to look.

This makes a significant shipped capability easy to miss and makes the architecture overview
appear inconsistent with the implementation.

## Verified behavior

- README names BYOK but does not name Model connections, ChatGPT subscriptions, or Codex App
  Server.
- The architecture diagram connects the Agent loop directly to a BYOK-only provider node and has
  no Model connection or subscription-adapter boundary.
- The canonical glossary already defines a Model connection as either provider subscription or
  BYOK.
- ADR-0014 documents the pinned Codex app-server transport and provider-owned authorization.
- ADR-0016 documents how Codex dynamic tools preserve Veduta's AgentRunner ownership and
  Surface-authoring boundary.
- The Model connection manual smoke records a successful real ChatGPT subscription run on
  2026-08-11.
- No existing open or closed issue owns top-level discoverability of this path.

## Goal

A newcomer can learn from README and the architecture overview that Veduta supports both BYOK and
ChatGPT subscription Model connections, understand at a glance where Codex App Server sits, and
follow links to the canonical lifecycle, security, protocol, and current-parity details. The
wording must distinguish shipped support from gated or unfinished work and must not imply that
Codex owns Veduta's Agent loop.
