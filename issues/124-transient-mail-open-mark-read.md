## What to build

Let a user open one result from a Mailbox Surface or identify one message in focused chat. Opening
starts a new Agent-path interaction, retrieves that exact message transiently, renders its readable
content only to the requesting authenticated client, and marks only that provider message read.
The Gmail connector removes UNREAD explicitly; the Himalaya Skill uses direct read and flag
commands deliberately rather than relying on incidental fetch behavior.

Raw content remains Untrusted. It may enter the current Agent turn because this is an explicit
interactive read, but the native Gmail tool or general execution result marks it transient so it is
not persisted in a Surface, session replay, Event, memory, notification, Trace, Automation state,
or backup. Durable state may retain only safe message/thread identity, selected headers, the
existing Mail summary, timestamps, and truthful provider mutation outcome.

Retrieval and read-state mutation are separate observable steps. If content retrieval succeeds but
the provider refuses the read mutation, show the content with a clear not-marked-read outcome; do
not claim atomic success or retry an unsafe mutation silently.

## Acceptance criteria

- [ ] Opening a result is an Agent-path action tied to the focused Space and exact account/message;
      a forged, stale, unknown, or other-Space reference returns one non-disclosing failure.
- [ ] The authenticated requester receives the readable message content, while another connected
      client or Space receives neither the content nor an identifying payload.
- [ ] Exactly the selected Gmail or generic message becomes read; no thread sibling, search result,
      summary result, or unrelated message changes state.
- [ ] Searches, summaries, Surface rendering, restart recovery, and merely focusing a result still
      leave unread state unchanged.
- [ ] Raw body and HTML are bounded and treated as Untrusted data; active content, remote loads,
      scripts, tracking pixels, and unsafe links never execute in the PWA.
- [ ] Reload, reconnect, server restart, session replay, export, and backup cannot recover the raw
      content after the transient view is gone.
- [ ] A read-state failure is visible and idempotently retryable without re-fetching or mutating a
      different message; a fetch failure performs no read mutation.
- [ ] Native Gmail/direct-Himalaya outcome parity, taint, transient-result handling, isolation,
      race, stale-reference, accessibility, and pnpm check pass.

## Out of scope

- Persisting original message content.
- Opening or downloading attachments.
- Dedicated Surface actions and polished acceptance coverage for marking unread, bulk read,
  archive, delete, move, label, star, spam, or folder operations; an explicit chat request may
  still use capabilities available to the Agent.
- Drafting or sending a reply.
