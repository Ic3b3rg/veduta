## What to build

Let an authenticated user add, inspect, reconnect, and remove independently named Gmail Mailbox
connections from the PWA. A connection is Gateway-wide and has a stable account identity: Spaces
may reference it, but the connection itself owns no Space, Surface, memory, notification, or
Automation.

Use the native Gmail API and OAuth. Request only the scopes required by the declared v1
capabilities, and keep client credentials, refresh tokens, and access tokens inside the existing
credential boundary. Authorization may verify account identity and capability availability, but it
must not list, fetch, import, summarize, or modify any message. Multiple Gmail accounts must coexist
without one account's credentials or provider ids overwriting another's.

Adopt compatible credentials from the quiesced legacy Gmail integration without retaining its
Space binding, Pub/Sub topic, subscription, Watch renewal, or automatic-ingestion semantics.
Connection UI must no longer ask for mail-push configuration.

## Acceptance criteria

- [ ] Two Gmail accounts can be authorized, named, reconnected, selected independently, and removed
      through authenticated PWA flows with stable non-secret connection ids.
- [ ] Completing or restoring a connection calls no Gmail message, thread, history, Watch, or
      modify endpoint; an account-profile/capability check is the only permitted mailbox-provider
      read.
- [ ] OAuth scopes map deterministically to the supported v1 operations and tests fail if a broader
      undeclared scope is requested.
- [ ] Secrets never enter chat, Agent context, URLs, logs, Events, Surfaces, connection records, or
      plaintext backups.
- [ ] A connection can later be referenced from two Spaces without either Space gaining the other
      Space's results, memory, or Automation state.
- [ ] A legacy Gmail configuration is reconciled idempotently into one passive connection without
      re-entering usable credentials and without starting a Watch.
- [ ] Removing one connection revokes or deletes only its own authorization state and leaves other
      connections and every Space intact.
- [ ] Restart, migration, multi-account, redaction, authorization-failure, and pnpm check pass.

## Out of scope

- Mail search, summaries, Surfaces, read-state mutation, replies, and Automations.
- A Space-specific credential or connection.
- Microsoft 365 or Gmail through Himalaya.
- Restoring Pub/Sub mail ingestion.
