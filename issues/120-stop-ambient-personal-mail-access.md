# 120 — Stop ambient personal-mail access on existing installations

> _This was generated by AI during triage._

## What to build

Existing installations can start Gmail Watch renewal and IMAP IDLE merely because a personal-mail
ingestion source is configured. Quiesce those mail-only sources so boot, reconnect, periodic
maintenance, and the act of connecting a mailbox cannot list, fetch, import, classify, mark, or
enqueue mail without an explicit user request or a confirmed Automation.

Keep Google Calendar Watch and generic HMAC webhook ingestion fully operational. Preserve the
existing Gmail and IMAP connection material behind a migration seam so later passive Mailbox
connection slices can adopt it without asking for credentials again. An older ingestion
configuration must boot safely, retain enough non-secret identity to migrate, and produce neither a
mail connection nor a recurring failure alert.

Record the pull-based personal Mailbox decision in ADR-0024. It supersedes ADR-0023 for personal
mail and narrows ADR-0005: events-first remains valid for explicitly authorized event sources, but
a personal mailbox is not an event source merely because it is connected.

## Acceptance criteria

- [ ] Starting or restarting the Gateway with legacy Gmail-mail and IMAP-IDLE sources performs zero
      Gmail mailbox, Gmail Watch, Pub/Sub renewal, IMAP, or SMTP requests.
- [ ] The same installation still accepts HMAC webhooks and renews configured Google Calendar
      watches with their existing filtering, quarantine, and health behavior.
- [ ] Legacy mail source records and secret references survive in a migration-safe form without
      resolving credentials, opening a socket, queueing mail, or emitting failure alerts.
- [ ] Connection alone creates no mail Event, Agent turn, Surface mutation, notification, read-state
      change, or message import.
- [ ] Onboarding and active documentation stop promising that connected personal mail is monitored
      automatically.
- [ ] ADR-0024, ADR-0005, ADR-0023, the security model, and the architecture describe one consistent
      pull-based boundary.
- [ ] Upgrade, restart, no-network, Calendar regression, webhook regression, and pnpm check pass.

## Out of scope

- Creating the replacement Gmail or generic Mailbox connection experience.
- Searching, summarizing, opening, or replying to mail.
- Physically deleting the dormant Watch and IDLE implementation; the final contract slice owns
  removal after both migrations exist.

## Blocked by

None - can start immediately.
