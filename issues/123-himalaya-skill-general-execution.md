# 123 — Operate generic IMAP and SMTP mailboxes through the Himalaya Skill

> _This was generated by AI during triage._

## What to build

Deliver the first command-backed Skill path. Add a Veduta-owned general execution tool to
AgentRunner, distinct from every inference provider's native command facility. A Skill may use it
for external CLIs, APIs, and setup commands with an explicit working directory, cancellation,
deadlines, bounded output, transient/sensitive-result handling, redacted diagnostics, and Trace.
The tool is general by design: do not add a mail-command allowlist or pretend arbitrary shell
semantics are a provider-neutral API. It is not assigned a domain-wide L1/L2 effect class and does
not inspect command text to manufacture Approval cards; the service account, container, or host is
the actual process boundary, while official Skills own Approval behavior and tests.

Bundle a first-party Himalaya connector Skill with concise instructions and focused references for
detecting a compatible `himalaya` on PATH, installing a reviewed compatible release when it is
missing, configuring named accounts, producing structured output, and using direct mailbox
commands. On an explicit setup request the Agent performs those technical steps itself; the user
supplies only provider choices, authorization, or secrets that cannot be derived. A missing binary
therefore puts the Skill into truthful setup mode instead of making it undiscoverable.

The authenticated PWA provides a safe credential/authentication interaction. Secrets stay outside
model context in the existing vault, an operating-system keyring, or a credential file consumed by
Himalaya; they never appear in commands, output, chat, Events, Surfaces, Trace, or backups. The
Agent may manage non-secret Himalaya configuration directly. Connection verification may test
IMAP/SMTP authentication and capabilities but must not list or fetch messages.

For a mail request, mailbox-assistant owns scope and result discipline while the Himalaya Skill owns
provider commands. Direct command output is Untrusted; summary flows bound it, route extraction
through the quarantined reader, persist only validated Mail summaries, and preserve unread state.
Gmail and Himalaya must converge on the same text and Mailbox Surface experience, not on identical
command schemas. Reconcile a compatible quiesced IMAP-IDLE source into a passive Mailbox connection
without starting IDLE or requiring credentials again.

## Acceptance criteria

- [ ] BYOK/fake and ChatGPT-subscription/fake turns receive the same Veduta-owned general execution
      tool through AgentRunner; provider-native command, patch, web-search, MCP, and approval
      facilities remain disabled.
- [ ] A harmless fixture CLI proves the execution tool is reusable outside mail and records command,
      working directory, duration, exit status, cancellation, and redacted outcome without a
      domain-specific adapter.
- [ ] General execution neither creates an Approval card nor claims to infer effect level from
      command text; typed external tools retain their existing L1/L2 enforcement unchanged.
- [ ] On an explicit setup request, the Agent reuses a compatible Himalaya on PATH or installs and
      verifies a reviewed compatible release; missing, incompatible, cancelled, and failed setup
      states produce truthful recovery guidance without harming Gmail or the Gateway.
- [ ] Two generic accounts can be added and tested through the generative PWA flow with stable ids
      and isolated credentials; the Agent performs the technical Himalaya configuration without
      requiring the user to type shell commands.
- [ ] Connection testing contacts only the configured IMAP/SMTP endpoints and fetches no mailbox,
      envelope, message, or attachment data.
- [ ] The same scoped search and newsletter-summary fixtures produce equivalent Mail summaries and
      Mailbox Surfaces for Gmail and Himalaya even though the connector tools and commands differ.
- [ ] Searches and summaries preserve the provider's unread state; the Himalaya Skill uses and
      verifies non-mutating commands against a scripted provider.
- [ ] The Agent can execute documented Himalaya commands directly, inspect help/version output, and
      use provider capabilities that do not yet have a dedicated Veduta adapter or Surface action.
- [ ] Raw provider output is bounded, marked Untrusted, omitted from durable session/Event/Surface/
      backup state when classified transient, and reduced to validated Mail summaries for durable
      results.
- [ ] Secrets do not appear in model context, command text, process arguments, environment dumps,
      logs, Events, Trace, sessions, Surfaces, or backups.
- [ ] A legacy IMAP-IDLE source migrates idempotently to a passive connection and never opens an
      IDLE session.
- [ ] General execution, setup, direct CLI, migration, outcome parity, timeout, cancellation,
      malformed-output, redaction, PWA, and pnpm check pass.

## Out of scope

- Claiming Microsoft 365 support without a verified modern OAuth or Graph connection.
- Opening a raw message, attachments, read-state mutation, replies, or Automations.
- First-party executable files bundled inside Skills; those enter in v1.1.
- A community Skill loader, Hub, marketplace, or upstream support guarantee for fork-added code.
- Claiming that general execution is a least-privilege sandbox or that every command effect can be
  classified structurally.
