# Research 27 — Popular external extensions as Veduta Hub proving cases

> Snapshot: **2026-09-30, 09:04 UTC**. Primary-source catalog metadata and publisher documentation only. Download counts can change; no package was installed, enabled, authenticated, or exercised. The proposed Veduta behavior is a product inference, not a measured implementation result.

## What “popular” means here

[ClawHub's public API](https://github.com/openclaw/clawhub/blob/main/docs/api.md#endpoints) offers separate `sort=downloads` listings for [Skills](https://clawhub.ai/api/v1/skills?sort=downloads&limit=20) and [plugins](https://clawhub.ai/api/v1/plugins?sort=downloads&limit=15). Its [specification](https://github.com/openclaw/clawhub/blob/main/specs/spec.md#skill) identifies public downloads as native ClawHub artifact downloads, separate from installation telemetry. [ClawHub telemetry documentation](https://docs.openclaw.ai/clawhub/telemetry#install-counts) defines Skill lifetime/current installs as unique users who reported installation and plugin installs as each user's first successfully reported install for a package. Reporting requires an authenticated CLI and can be disabled; uninstall does not decrement counts. The listing's `stats.installs` field is shown below as reported, without assigning it to a specific Skill lifetime/current counter. None of these numbers measures active use or successful functional setup. The rankings below use **downloads**, with the listing's installs displayed separately. A security scan verdict is not a functional compatibility test.

The [Hermes plugin catalog](https://hermes-agent.nousresearch.com/docs/user-guide/features/plugin-catalog) publishes a [CDN snapshot](https://hermes-agent.nousresearch.com/docs/api/plugins.json) of reviewed, pinned entries with **cached GitHub repository stars**. It does not publish plugin installs or usage. Repository stars can be for a larger parent project, so they cannot be compared with ClawHub downloads or treated as plugin adoption. The snapshot contained 348 entries; `web-search-plus` ranked eighth by cached repository stars (416), second within the web category. These ranks are a calculation over the cited catalog snapshot.

## Selection and sequencing implication

These five cover three different failure modes that a catalog preview alone would miss: **CLI/OAuth or local-file setup** (`gog`, Obsidian), **automatic lifecycle hooks** (self-improving-agent, Web Search Plus), and a **stateful communication channel** (WhatsApp). An end-to-end demonstration would be a user pasting or selecting the existing package, Veduta showing the exact artifact and requirements, approval of each needed capability, a tested activation, and an installed-state UI that reflects actual readiness. This follows the owner's full-function installation requirement, not a current Veduta capability. The user wants several **popular existing** extensions functioning, including a real executable plugin; a trivial custom example does not satisfy that proof.

For an **earlier, narrower OpenClaw code-plugin port** than WhatsApp, [@openclaw/brave-plugin](https://clawhub.ai/openclaw/plugins/brave-plugin) ranked tenth in the [same plugin snapshot](https://clawhub.ai/api/v1/plugins?sort=downloads&limit=15), with **12,729 downloads and 63 reported installs**. Its [official plugin reference](https://docs.openclaw.ai/plugins/reference/brave) describes Brave Search provider registration; it requires `BRAVE_API_KEY` or plugin configuration and Gateway restart, with an OpenClaw host-version floor of 2026.4.10. This proves external code, credentials, and tool/provider registration without a messenger's persistent account/session lifecycle. It remains an OpenClaw-native provider plugin, so the compatible Veduta result would be an adapted provider integration, not running the original module unchanged. Its lower adoption signal than WhatsApp should be explicit when prioritizing it. Web Search Plus spans multiple providers and a startup hook, so it is an advanced Hermes-native proving case rather than a quick initial port.

The candidates are **not interchangeable**. `gog` and Obsidian are Skill procedures that require separately installed tools and reachable data. Self-improving-agent is a Skill bundle with an OpenClaw hook. WhatsApp and Web Search Plus are executable, host-native plugins. The shared Agent Skills format does not create host APIs; [Agent Plugins v1](https://agent-plugins.org/specification) standardizes Skills and MCP components but leaves native hooks/channels/providers outside its common floor. This is why direct 100% import is not a defensible acceptance criterion for these five without tested Veduta adaptations.

The higher-starred Hermes catalog entries `hindsight` (43,265 repository stars) and `honcho` (7,403) were **not** selected merely for their parent repository popularity: both are memory provider packages rather than straightforward integration tests, and Hindsight advertises knowledge-graph behavior that [Veduta's current anti-requirements](../../ARCHITECTURE.md#7-what-we-do-not-build-anti-requirements) reject. Excluding them is a product-architecture decision, not evidence that Web Search Plus has more users.

## Verification gaps

- All numbers are one live API snapshot. ClawHub's published telemetry model explains reported installs but cannot establish active use, enabled state, working credentials, or successful task execution.
- Hermes provides no comparable plugin adoption metric in its public catalog. Its repository-star ranking is only a discovery signal.
- Exact source-to-artifact equivalence for the OpenClaw WhatsApp `2026.9.7` release was not checked. The ClawHub [security record](https://clawhub.ai/api/v1/packages/%40openclaw%2Fwhatsapp/versions/2026.9.7/security) returned `verdict: review` with `scanStatus: clean`; neither status proves runtime compatibility.
- `gog` and Obsidian setup instructions show drift against maintained upstreams. Their real installation and representative actions need a bounded proof before Veduta promises them as working.
- No package was installed or executed for this research. A later implementation must use clean test accounts and data and verify behavior at runtime, including restart/reconnect and relevant error paths.
