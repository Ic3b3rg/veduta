# Familiar Chat prototype

Throwaway proposal for [#228](https://github.com/Ic3b3rg/veduta/issues/228), following
[research 42](references/42-generative-ui-chat-interaction.md). The earlier A/B prototypes were
rejected. This branch demonstrates one composition requested in the subsequent discussion:
a persistent right-hand Chat on desktop and a full-screen mobile Sheet reached through a
Chat icon button. The owner accepted this composition on 10 October 2026 and requested an
icon-only mobile button. This remains a design prototype, not production implementation.

## Run and try

```sh
pnpm install --frozen-lockfile
pnpm prototype:chat
```

Open <http://localhost:5185/app/space/health?prototype=familiar-chat> on the same computer.
The server binds to loopback. `localhost` on a phone refers to the phone, not the development Mac.
Use the shared browser's phone viewport to inspect this local version.

1. On desktop, read the Chat beside the Health Space. At widths below 960 px, tap the speech-bubble
   button, whose accessible name and tooltip are **Open Chat**.
   Opening the Sheet focuses its heading, not the composer.
2. Choose **Explain the plan** for a long Markdown response. Scroll up while it arrives; the
   reading position should stay where you left it. **Go to latest message** resumes following.
3. Type **Move Friday's walk to Saturday** and send using the arrow. Enter adds a line break;
   Ctrl/Cmd+Enter also sends. Replies are preset, not generated by a model.
4. Choose **Review change**. Inspect the current/proposed day, time and duration, then accept
   or decline. Accept changes the sample Weekly plan; decline leaves it alone. Closing review
   leaves the decision pending. A pending review stays reachable outside the closed mobile Chat.
5. Write a multiline draft and scroll to an earlier reply. Close and reopen mobile Chat. The
   draft, Chat reading position and Space position survive. The **Weekly plan** reference
   intentionally returns to that Surface.
6. Use the header model control to try the two fields in a modal. The choices only affect the
   sample label. Use **Demo → Restart demo**, or reload, to restore the initial state.

## Boundaries

- Reuses the real Space navigation, Space/Surface components, catalog Markdown renderer,
  Button, NativeSelect and focus-managed Radix Sheet. Surface fixtures pass `SurfaceSchema`.
- In-memory messages, Surface changes, Pin/order choices, model choices and review outcomes.
  No daemon, authentication, provider, Gateway API/Chat WebSocket, database or VPS dependency.
- Development-gated entry on the existing Space route. The surrounding Home/System samples
  provide navigation context; the Chat experiment belongs to Health.
- The review demonstrates a complete replacement of one fixture entry. It does not implement
  the general multi-operation comparison, stale-version authority or recovery work in
  [#227](https://github.com/Ic3b3rg/veduta/issues/227).
- A Sheet provides modal focus, Escape, explicit close and focus return. Swipe-to-dismiss is
  not implemented. Do not infer gesture behavior from its bottom entrance animation.
- Browser resizing exercises CSS geometry, not a physical Android keyboard. That remains a
  separate device check before accepting a production design.
- Reload deliberately resets the demo. Production Chat remains Gateway-owned and durable.
  Do not promote these simulated state transitions into the application runtime.

This branch is retained as evidence of the accepted direction. Production work must integrate
the real Gateway-owned Chat and Pending decision lifecycles rather than ship the simulated state.
